# 업무 검색 정확성·사용 흐름 점검

2026-09-13. 운영 자료는 수정하지 않았으며, 공개 검사에는 실제 고객 정보가 아닌 합성 자료를 사용합니다.

## 접수된 문제와 원인

업무일지에 표시된 `106동 1503호`를 그대로 검색하면 결과가 없었습니다. 화면은 동·호 접미사를 붙여 하나의 주소로 보여주는데, 검색은 저장된 건물명·동·호수를 각각 따로 비교하고 있었습니다. 통합검색의 매물 검색에 있던 주소 조합 처리도 업무일지 등에는 일관되게 적용되지 않았습니다.

여러 물건을 기록한 업무에서는 두 번째 물건이 검색에 맞아도 첫 물건을 대표 주소로 표시했습니다. 이 때문에 결과가 나와도 다른 물건을 찾은 것처럼 보이고, 바로 누르는 매물 이력도 기대한 물건과 달랐습니다.

## 수정한 범위

| 문제 | 수정 |
| --- | --- |
| 표시된 동·호수 조합으로 검색하면 누락 | `106동 1503호`, `106동1503호`, `106 1503`, `106-1503` 및 건물명 조합을 같은 물건의 주소 조건으로 조회 |
| 화면마다 주소 검색 기준이 다름 | 업무일지·통합검색의 업무/매물·매물 관리/불러오기·연결 매물의 할 일에 공통 검색 적용 |
| 여러 물건 중 검색에 맞지 않는 주소 표시 | 검색에 맞는 첫 물건을 대표로 표시하고 ‘검색 일치 물건’ 안내; 저장된 물건 순서와 전체 개수는 유지 |
| 비슷한 번호나 서로 다른 물건 조건이 섞일 위험 | 명시한 동·호는 숫자 전체를 비교하고, 두 조건이 한 물건에 모두 맞아야 주소로 일치 |
| 새 검색어 옆에 이전 결과·건수가 잠시 남음 | 새 조건의 검색 중에는 이전 결과·건수 숨김; 조회가 끝나기 전 CSV/더보기 잠금 |
| 통신 실패와 정상 0건을 혼동 | 실패 안내·같은 조건 재시도 제공, 정상 조회 후에만 빈 결과 표시 |
| 저장 후 같은 조건 재조회 때 읽던 위치 이동 | 같은 조건의 갱신은 기존 목록을 유지하고 ‘갱신 중’ 표시 |
| 전화번호 구분자 때문에 고객 누락 | 고객 ID/연락처는 하이픈·공백·괄호 차이를 무시하고 조회 |
| `%`, `_`를 입력하면 검색 범위가 뜻밖에 넓어짐 | 검색 문자를 SQL 와일드카드가 아닌 실제 문자로 처리 |
| CSV가 모든 연결 물건까지 포함하는 것처럼 보임 | 현재 조건의 전체 업무를 내보내되 물건은 업무당 대표 1건임을 화면·헤더·완료 안내에 명시 |

주소가 아닌 고객명·업무 내용 검색도 유지합니다. 따라서 주소 문자열이 상담 내용에 직접 적힌 업무도 검색될 수 있습니다. ‘검색 일치 물건’ 표시는 연결 물건 자체가 조건에 맞을 때만 붙습니다. 검색 결과 순서는 기존처럼 업무일 최신순이며, 같은 날은 최근 수정순입니다.

## 반복해서 불편이 발견된 이유

기존 검증이 화면 가독성, 개별 검색 함수, 단일 건물명 검색 등에 나뉘어 있었습니다. ‘화면에서 본 주소를 입력 → 여러 물건 중 일치한 주소 확인 → 그 물건의 이력 열기’라는 실제 사용 순서를 충분히 검증하지 못했습니다. 이전 자동 테스트 통과 수만으로 검색의 실사용 정확성을 보장할 수는 없었습니다.

이번에는 실제 API 핸들러를 메모리 SQLite에 연결해 화면별 검색 결과·건수·페이지·대표 물건을 함께 비교합니다. 긍정 사례뿐 아니라 `1106동`, `15030호`, 서로 다른 물건의 동·호 조합, 특수문자, 건물명 끝의 ‘동’ 및 숫자, 전화번호와 주소의 혼동도 회귀 검사에 포함합니다. UI는 입력 중·응답 대기·실패·재시도·정상 0건·동일 조건 갱신을 나누어 확인합니다.

## 확인 범위

타입 검사·배포용 빌드·자동 테스트 137개 통과. 이 중 이번에 추가한 22개는 실제 API/SQL 주소 검색과 업무일지 상태·이력 연결·CSV 흐름의 회귀 검사입니다.

브라우저에서는 현재 API 처리기와 읽기 전용 합성 SQLite(112개 업무)를 연결해 다음을 확인했습니다. 고정 검색 결과만 돌려주는 화면 모형 검사가 아닙니다.

- PC에서 표시 주소 검색, 두 번째 연결 물건의 대표 표시와 해당 매물 이력 열기, 닫은 뒤 검색어 유지
- 주소 표기 전환, 업무구분과 결과 건수, 지연 응답 중 이전 결과 숨김·CSV 잠금
- 의도적으로 발생시킨 503 응답과 같은 조건 재시도, 정상 0건 표시
- 검색 결과 CSV의 실제 2개 업무·대표 주소, 통합검색의 업무 2건/매물 1건 일치
- 390px 휴대폰 화면과 큰 글씨에서 페이지 가로 넘침 없음, 동·호수 단위 줄바꿈
- 매물 관리·연결 매물 할 일의 동일 주소 검색, 화면을 오간 뒤 업무일지 검색 조건 유지

## 남는 한계

- 자연어 의미 검색이나 오타 교정 기능은 아닙니다. 동·호 표기가 없는 숫자 일부는 기존처럼 부분 검색입니다.
- 같은 업무의 여러 물건이 조건에 맞으면 그중 저장 순서상 첫 일치 물건을 대표로 표시합니다. 나머지는 ‘외 N건 보기’에서 확인합니다.
- CSV의 대표 물건 1건 구조는 유지됩니다. 모든 관계를 복원하는 전체 백업과는 다릅니다.
- 이번 점검은 검색 정확성과 관련 화면 상태에 집중했습니다. 운영 자료 저장·삭제, 모든 과거 데이터 변형과 모든 기기 조합을 재현한 전체 무결성 보증은 아닙니다.
