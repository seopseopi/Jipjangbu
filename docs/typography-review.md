# 글꼴·줄바꿈 점검 · 2026-09-16

## 후속 조정: 과한 굵기 완화

첫 배포 후 “글씨가 너무 강하게 들어온다”는 피드백에 따라 Noto Sans KR 대신 [Pretendard v1.3.9](https://github.com/orioncactus/pretendard/tree/v1.3.9)를 적용했다. 아래 첫 점검 기록은 당시 변경 내용을 보존한 것이다.

- 현재 기준: 본문·메모 400, 날짜·고객명·업무구분 600, 화면·구역 제목 700. 글씨색과 기본/큰 글씨 크기는 유지하고 기본 줄 높이는 1.7로 조정했다.
- 가변 WOFF2 서브셋 92개를 자체 제공하며 공식 라이선스를 동봉한다. 사용하지 않는 이전 글꼴 파일은 배포에서 제외한다.
- CSS 계약 테스트도 단순히 굵은 글씨를 요구하지 않고 본문·정보·제목의 굵기 차이와 날짜·고객·업무구분의 일관성을 검증하도록 갱신했다.
- 브라우저의 실제 계산 스타일에서 본문 400 / 정보 600 / 제목 700 및 Pretendard 로딩을 확인했다. 화면 비교에는 합성 자료만 사용했다.

## 변경

- Noto Sans KR 가변 글꼴을 사이트에서 직접 제공한다. 로컬 확인에서 `next/font`의 CSS 변수와 폰트 선언이 적용되지 않는 경우가 있어 명시적인 `@font-face`와 루트 변수를 사용한다. Unicode 서브셋과 `font-display: swap`으로 필요한 문자만 내려받고 로딩 중에도 내용을 표시한다.
- 본문 16px / 큰 글씨 18px, 진한 글씨·경계 대비는 유지한다. 동일한 조회 영역의 날짜·고객명·업무구분은 같은 크기와 굵기를 사용한다.
- 홈 할 일은 날짜·완료 버튼 다음 줄에 제목을 전체 폭으로 배치한다. 날짜는 한 줄로 보존하고 `기한 지남`은 별도 줄로 표시한다. 메모·완료 확인·정렬은 변경하지 않는다.
- 월간 달력 칸은 공통 정보 크기를 15px / 큰 글씨 17px로 조정한다. 1180px 이하에서는 날짜별 일정 목록을 사용해 업무구분이 좁은 칸에 쪼개지지 않게 한다.
- 매물 목록의 상태·날짜 열을 넓히고 말소일도 한 줄로 표시한다. 휴대폰 업무일지는 정보 묶음 단위로 줄을 바꿔 날짜 옆 업무 배지를 압축하지 않는다.
- 홈의 오늘 업무 버튼을 `오늘 업무 보기`로 간결하게 바꾼다. 최근 수정순 오늘 업무 팝업 연결은 그대로 유지한다.
- 폰트와 라이선스의 정확한 경로만 로그인 전 GET/HEAD를 허용한다. 업무 API 인증이나 쓰기 권한은 변경하지 않는다.

## 검증 범위

실제 고객 자료 대신 합성 고객·매물·여러 연결 매물·긴 이름·여러 줄 메모를 사용했다. 브라우저의 업무 API 응답을 가로채고 쓰기 요청은 차단했으며 운영 DB를 수정하지 않았다.

- Chromium 로컬 화면: 1440·1280·1024·840·390·360·320px, 기본/큰 글씨 모드, 홈·업무일지·매물·고객·달력·현황의 총 84개 조합.
- 위 조합에서 페이지 가로 넘침과 날짜·일반 업무 배지·짧은 동작 버튼의 불필요한 줄바꿈이 없는 것을 DOM 치수로 확인했다. 긴 이름·주소·메모의 자연스러운 줄바꿈은 유지한다.
- 오늘 업무 → 업무 내용 → 업무 복사·새 업무 등록 → 취소 흐름을 확인했다. 업무 내용/복사 화면은 큰 글씨 모드에서 1440·390·320px의 날짜·버튼 및 팝업 가로 넘침을 추가 점검했다. 저장은 실행하지 않았다.
- 새 글꼴의 실제 로딩을 `document.fonts`로 확인하고 홈·업무 내용 화면을 캡처해 육안 검토했다. 캡처와 일회성 측정 도구는 Git에서 제외되는 `output/playwright/wrap-review/`에 보관한다.
- lint·타입 검사·배포용 빌드·회귀 테스트 486개 통과. 폰트 파일 실재/형식/라이선스, 공개 경로 한정, 응답 캐시 보존, 날짜 배치 계약을 검증한다.

자동 레이아웃 점검은 위 합성 자료와 Chromium 범위이며 모든 브라우저·임의의 장문에 대한 보증은 아니다. 장문은 잘라 숨기지 않고 읽을 수 있도록 줄바꿈한다.
