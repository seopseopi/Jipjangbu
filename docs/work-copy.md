# 업무 복사 설계

[사용 가이드](usage.md) · [문서 모음](README.md)

## 목표와 흐름

기존 상담·방문 기록을 다시 입력하지 않고 새 업무의 초안으로 사용합니다.

**업무 내용 보기 → 업무 복사 → 새 업무 등록에서 수정 → 새 업무로 저장 → 새로 저장한 업무 내용 보기**

홈·업무일지·달력·검색·고객/매물 이력에서 열리는 공통 읽기 화면에 적용합니다. 복사 버튼을 누르는 것만으로는 자료를 저장하지 않습니다. 별도 확인 팝업 없이 초안을 열고, 저장 버튼으로 등록 의사를 확정합니다.

## 복사 기준

| 항목 | 동작 |
| --- | --- |
| 고객 | 기존 고객 연결 유지. 고객 자체를 중복 생성하지 않으며 다른 고객으로 변경 가능 |
| 업무구분·내용 | 읽고 있는 저장된 기록을 복사. 임의 접두사나 과거 이력은 본문에 추가하지 않음 |
| 연결 매물 | 최대 10개의 입력 순서, 구분·건물·동·호수·타입·매매/전세/월세·물건지 유지 |
| 업무일 | 오늘 날짜로 시작. 원본 날짜를 안내하고 직접 변경 가능 |
| 업무·물건·이력 ID | 원본 식별자를 재사용하지 않고 서버에서 새로 생성 |
| 생성·수정 시각·엑셀 이관 ID | 원본에서 복사하지 않음 |

과거 기록의 가격을 현재 매물 가격으로 몰래 바꾸지 않습니다. 복사 화면에서 날짜와 가격이 **원본 기록 기준**임을 알리고 검토할 수 있게 합니다. 매물 상태 변경 업무는 기존 등록 규칙대로 새 이력과 현재 상태를 계산하므로, 원본 업무가 보존되는 것과 현재 매물 상태가 유지되는 것은 별개입니다.

## 흐름 보호

- 명부를 준비하는 동안 즉시 대기·취소 화면을 표시합니다. 실패하면 복사 원본을 유지한 채 재시도합니다. 취소한 요청의 늦은 응답은 화면을 다시 열지 않습니다.
- 화면에 읽은 저장 내용으로 독립된 초안을 만듭니다. 복사 중 원본을 재조회해 사용자가 보지 않은 내용으로 교체하지 않습니다.
- 수정 화면의 복사도 같은 동작입니다. 저장하지 않은 수정 내용이 있으면 제외된다는 확인을 먼저 받습니다.
- 취소는 원본 읽기와 원래 이력·필터를 보존합니다. 복사 후 편집한 내용을 버릴 때는 기존 이탈 확인을 유지합니다.
- 복사 폼에는 원본 삭제 버튼을 표시하지 않습니다. 새 업무 저장은 `POST /api/work-logs`이며 원본 수정 API를 호출하지 않습니다.
- 저장 중 연속 클릭·Enter는 동기 잠금으로 중복 전송을 차단합니다. 저장 실패 시 입력을 유지하고 잠금을 해제합니다. 통신 단절 후 재시도까지 보장하는 서버 측 멱등성 기능은 별도 범위입니다.
- 저장 성공 후 서버가 반환한 새 업무를 즉시 보여줍니다. 불필요한 재조회 없이 새 ID를 사용하며, 목록과 원래 이력은 별도로 갱신합니다.

## 검증 기준

원본 불변, 오늘 날짜, 10개 매물·0원·여러 줄 원문 보존, 메타데이터 제외, 수정 후 신규 등록, 저장 중 중복 클릭, 실패·재시도·취소, 복사 후 새 기록 열기, 기존 수정 흐름 유지가 통과해야 합니다. 검증은 합성 자료만 사용하며 운영 자료에 복사 업무를 생성하지 않습니다.
