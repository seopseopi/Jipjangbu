# 가독성·사용 흐름 점검

## 2026-09-13 · 과거 업무를 수정한 내용이 이력에서 안 보이는 문제

기존 이력 상단은 엑셀 원본 메모만 표시했고, 날짜도 업무일만 보여주었습니다. 과거 업무에 연락처를 추가해 정상 저장해도 상단과 날짜가 그대로여서 저장 누락으로 오해할 수 있었습니다.

- 매물 이력 상단에서 **최근 저장한 업무 내용**을 먼저 보여주고, 엑셀 원본 메모는 별도 접기 영역에 보존합니다. 과거 업무를 최근에 정정한 경우도 포함합니다.
- 원래 **업무일**과 **최근 저장** 시각을 구분하고 저장 시각은 한국 시간으로 표시합니다. 업무 생성·정정 모두 저장에 해당하며, 각 수정 버전의 차이를 보관하는 별도 감사 로그는 아닙니다.
- 아래 이력의 업무일순 정렬과 현재 매물 상태·가격의 선정 기준은 바꾸지 않습니다. 상단 최근 저장 내용과 현재 상태·가격을 별도 표제로 구분합니다.
- 업무 작성 중 펼치는 매물 이력과 고객 업무 이력에도 같은 날짜 기준을 적용합니다. 저장 시각이 없는 원본에는 시각을 추측하지 않습니다.
- 기존 조회에 업무 저장 시각을 함께 반환하는 변경으로, 스키마·저장 방식·운영 기록은 변경하지 않습니다. 과거 업무 정정, 미래 업무일, 한국 시간 날짜 경계, 원문 보존을 합성 API·화면 구성 검사로 검증합니다.
- 전체 자동 검사 334개와 코드·타입 검사 및 배포 빌드가 통과했습니다. 이번 검증은 실제 API/SQL 및 React 화면 구성·이벤트 테스트이며, 별도의 브라우저 시각 검사는 수행하지 않았습니다.

## 2026-09-13 · 여러 매물을 읽기 쉽게 정리

모든 매물을 펼쳐 보이게 한 뒤 반복되는 단지명·이력 안내와 좁은 표가 복잡해진 부분을 다시 정리했습니다.

- 업무일지는 날짜·업무구분·고객을 머리말에 모으고, 넓은 본문과 연결 매물을 별도 영역으로 구분합니다. 반복되던 주소 아래의 이력 안내 대신 주소 자체를 누릅니다.
- 연속된 같은 단지는 이름을 한 번만 표시하고 동·호수를 묶어 보여줍니다. 모든 물건과 입력 순서를 유지하며, 나중에 다시 나온 단지를 앞쪽으로 옮겨 합치지 않습니다. 각 주소는 정확한 매물 이력으로 연결되고 검색에 일치한 주소만 표시합니다.
- 목록 본문은 5줄 미리보기, **내용 보기**는 생략 없는 원문입니다. 상세 화면은 장식 카드 대신 주소·타입·가격·물건지·업소를 나란히 비교하는 행으로 표시하고 좁은 화면에서는 물건별로 이어서 읽습니다.
- 홈·이력·검색·예정 목록도 공통 주소 표시를 사용합니다. 달력은 같은 단지의 이름 반복을 줄이면서 엑셀의 업무 유형별 고객/물건 중심 기준과 각 물건의 단독·업소·고객 ID 표기를 유지합니다.
- 자동 검사 **301개 통과**. 이번 검사에는 열 물건의 원순서·전체 주소·각 이력 연결, 재방문 단지, 불완전한 주소, 본문/물건 영역 분리, 달력 PC/모바일의 같은 표시 기준이 포함됩니다. 합성 자료로 검증했으며 운영 자료를 변경하지 않았습니다.
- Chromium에서 1440px PC와 390px 휴대폰·큰 글씨 모드로 업무일지·읽기 상세·달력·고객 이력을 직접 확인했습니다. 열 물건을 모두 유지하고 가로 넘침이 없으며, 같은 단지 제목은 한 번만 표시됩니다. 읽기 화면에서 명시적으로 수정에 진입하고 취소하면 읽기 화면으로 돌아옵니다.
- 고객 이력의 기존 flex 스타일이 주소 목록의 grid를 덮던 충돌을 해소하고, 데스크톱 달력의 업무 제목·더보기도 큰 글씨 설정을 따르게 했습니다.

자동 검사는 화면 구조와 동작의 회귀 확인이며, 모든 실기기에서의 시각적 완성도나 실사용 오류가 없음을 보장하지 않습니다. 이전 브라우저 점검 범위는 아래에 별도로 남깁니다.

## 2026-09-12 · 긴 기록과 화면 이동 점검

2026-09-12 기준. 실제 고객·매물 자료를 변경하지 않고, 긴 이름·여러 문단·공백 없는 장문이 있는 합성 자료로 확인했습니다.

| 발견한 불편 | 개선 |
| --- | --- |
| 매물 메모 옆 버튼과 가격이 내용 폭을 줄임 | 가격·원문 메모·실행 버튼을 별도 행으로 분리, PC 이력 창 최대 960px |
| 이력의 날짜와 긴 고객명이 본문 폭을 차지 | 날짜·상태·고객명을 위에, 메모를 다음 줄 전체 폭에 표시 |
| 검색에서 긴 주소와 일치하는 메모 부분이 숨음 | 이름·주소 전체 줄바꿈, 검색어 주변 메모 요약과 생략 표시 |
| 방향키로 선택한 고객이 목록 밖에 숨음 | 검색 목록만 최소한 자동 스크롤, 고객 이름과 ID 별도 줄 |
| 업무 수정의 내용 창이 3줄이라 장문 검토가 어려움 | 최소 6줄, 입력 줄 수에 따라 최대 14줄, 수동 크기 조절 유지 |
| 고객 비고의 문단이 합쳐지거나 긴 ID가 잘림 | 원문 줄바꿈 보존, 긴 이름·ID·비고 줄바꿈 |
| 휴대폰 달력을 옆으로 밀어야 함 | 날짜순 세로 일정 목록, 전체 주소·고객명과 내용 미리보기, 하루 전체 업무 열기 |
| 빈 달력 월 값으로 오류 발생 가능 | 유효한 월 유지, 월·업무구분 변경 중 이전 조건의 기록 표시 방지 |
| 할 일 제목 옆 기한이 공간을 압박하고 확대 글씨가 일부 누락 | 기한·연결 정보 줄바꿈, 메모·상태·연결명 글씨 확대 반영 |
| 설정에서 건물 분류를 펼칠 수 있는지 알기 어려움 | 펼침 화살표와 건물별 목록 표시 |

### 당시 확인 범위

- 자동 검사 115개 통과. 새 검사에는 실제 컴포넌트의 이력 원문 보존·업무 열기, 고객 선택 키보드 동작, 달력 경계·필터 전환, 검색어 주변 요약이 포함됩니다.
- Chromium 테스트 브라우저에서 홈·할 일·업무 현황·업무일지·매물·고객·달력·설정을 390px / 840px / 1280px 너비와 큰 글씨 설정으로 순회했습니다. 페이지 전체와 점검 대상 주요 텍스트의 가로 넘침이 없었습니다. 태블릿의 넓은 관리 표는 기존 표 내부 스크롤을 유지합니다.
- PC 매물 이력의 메모 폭 872px, 휴대폰에서는 모달 가로 넘침 없이 원문을 표시했습니다. 버튼은 메모 카드 아래에 있습니다.
- 업무 수정 중 고객 이력을 열어도 입력 내용이 유지됩니다. 고객 검색의 9번째 항목까지 방향키로 이동했을 때 선택 항목이 보이고, 부모 모달의 스크롤 위치는 변하지 않았습니다.
- 달력 월 입력 지우기, 일정에서 업무 열기, 건물 분류 펼치기, 검색 결과의 전체 주소·16px 확대 메모 표시를 확인했습니다.

목록의 내용 미리보기와 검색 요약은 원본 저장값을 변경하지 않습니다. 이력·업무 화면에서 전체 내용을 확인할 수 있습니다. 운영 자료 저장·삭제와 모든 실기기·브라우저 조합을 이번 화면 점검에서 재현한 것은 아닙니다.
