# 엑셀 기능 분석 및 이관 기준

## 기준 통합문서

- 개발 기준: `업무일지(개발필요).xlsb`
- 참고 기준: `업무일지(원본).xlsb`
- 공통 5개 시트를 개발 기준으로 사용하며 원본의 추가 화면도 참고함
- 두 파일의 `frmCalendar.ShowCalendar` 표시 분기는 동일함(폼 메타데이터 GUID·컨트롤명 대소문자는 다름)
- 원본에만 수동 현황 확인용 시트 6개가 추가로 존재함

## 웹으로 옮긴 동작

엑셀은 고객, 묶음 업무, 물건 세부항목, 현재 매물 목록을 중심으로 동작합니다. 한 업무 ID 아래 최대 10개 물건을 저장하고, 매물 관련 업무가 저장되면 물건구분·건물명·동·호수를 기준으로 매물 상태를 갱신합니다. 고객 이력, 물건 이력, 월간 달력도 현재 및 과거 업무를 함께 조회합니다.

## 달력의 업무종별 표시 기준

두 XLSB의 `frmCalendar.ShowCalendar`를 읽기 전용으로 추출해 현재·과거 업무의 두 표시 분기를 대조했습니다. 매크로 실행이나 원본 수정은 하지 않았습니다.

| 업무 | 일반 고객의 첫 표시 |
|---|---|
| 매물등록·매물수정·매물취소·타계약확인·경매확인 | 각 물건 주소 |
| 가계약·계약서작성·중도금·잔금·계약취소 | 각 물건 주소 + 물건지·업소. 비었거나 `마전현대`면 `단독` |
| 전화·방문·예약·예정·계약파기 등 그 외 업무 | 고객명. 연결된 물건은 별도 줄로 모두 표시 |

고객명에 `부동산`이 포함되면 위 매물·계약 10종은 주소 옆에 고객 ID를 표시합니다. `자체결정`도 해당 10종에서 고객 ID를 사용합니다. 일반 상담은 부동산 고객의 ID와 이름을 함께 보여 줍니다. 단, `부동산써브`는 엑셀과 동일하게 일반 고객 표시 규칙을 적용합니다.

업무별 모든 물건을 원래 순서로 표시합니다. 엑셀의 동일 문구 묶음 대신 웹에서는 서로 다른 업무 ID를 별도 기록으로 유지하며, 같은 날 4건을 넘으면 날짜 전체보기로 연결합니다. 달력의 표시 분류와 매물 상태를 바꾸는 업무 분류는 별도 규칙입니다.

## 원자료 규모

- 고객 행 609개
- 현재 업무 세부행 284개, 과거 업무 세부행 1,848개
- 업무 ID 1,785개, 세부행 합계 2,132개
- 매물 행 357개
- 업무구분 28개, 물건구분 6개

## 정합성 보완 규칙

- 중복 고객 ID 1건은 최신 정보와 비고를 합쳐 한 고객으로 보존
- 고객목록에 없는 업무 고객 ID 8개는 기존 ID를 이름으로 사용해 보완 등록
- 동일 업무 ID 안에서 공통 정보가 다른 오래된 4건은 정보 손실을 막기 위해 별도 업무로 분리
- 같은 물건의 종료 후 재등록 중복 1건은 현재 상태를 유지하고 과거 내용은 이력에 합침
- 실제 개인정보와 원본 엑셀 파일은 GitHub에 저장하지 않음
